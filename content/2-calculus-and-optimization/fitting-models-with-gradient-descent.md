*Lecture 6 · [[2-calculus-and-optimization/index|Calculus and optimization]] · combines [[2-calculus-and-optimization/gradient-descent|gradient descent]] and [[2-calculus-and-optimization/autograd|autograd]] · next: [[3-linear-models/linear-regression|linear regression]]*

> [!abstract] In one breath
> To learn parameters $\theta$ from data $\{(x_i,y_i)\}$, write an **objective** such as the mean squared error $\frac1N\sum_i(y_i-f(x_i;\theta))^2$. For one data point the model plus the loss is a computational graph whose seed is the loss, so backpropagation gives $\nabla_\theta\ell$; over the dataset the gradients simply add (or average). Gradient descent on $\theta$ then fits the model. In PyTorch: `loss.backward()`, an in-place update under `torch.no_grad()`, clear the gradients, repeat.

## What it is

The ingredients of the course's first machine-learning problem:

1. **Data** $\mathcal D=\{(x_i,y_i)\}_{i=1}^N$, with ground-truth outputs $y_i$.
2. **Model** $f(x;\theta)$ — the semicolon separates the input $x$ from the learnable **parameters** $\theta$. Here $f(x;a,b,c)=ax^2+bx+c$.
3. **Objective** (loss, cost) — how wrong the model is on the data:
$$
\ell_{\text{mse}}(\theta)=\frac1N\sum_{i=1}^N\bigl(y_i-f(x_i;\theta)\bigr)^2 .
$$
Squaring makes positive and negative errors count the same.
4. **Learning algorithm** — [[2-calculus-and-optimization/gradient-descent|gradient descent]] on $\theta$:
$$
\theta^{(k+1)}=\theta^{(k)}-\alpha\nabla_\theta\ell_{\text{mse}}\bigl(\theta^{(k)}\bigr),
\qquad\text{i.e.}\quad a\leftarrow a-\alpha\frac{\partial\ell}{\partial a},\ b\leftarrow b-\alpha\frac{\partial\ell}{\partial b},\ c\leftarrow c-\alpha\frac{\partial\ell}{\partial c}.
$$

## What you should know

- The four ingredients above and the notation $f(x;\theta)$, $\nabla_\theta$.
- The loss is the **seed node**: parameters are input nodes of the graph, and their adjoints are $\partial\ell/\partial\theta$.
- Per-example gradients of the squared error, e.g. $\dfrac{\partial}{\partial a}(y_i-ax_i^2-bx_i-c)^2=-2x_i^2(y_i-ax_i^2-bx_i-c)$.
- **Linearity:** the gradient over the dataset is the sum (or mean) of the per-example gradients, so one `backward()` on the mean loss is enough.
- The NumPy loop (hand-derived gradients) and the PyTorch loop (autograd), and the five PyTorch details: `requires_grad`, `backward()`, `no_grad` + in-place update, clearing `.grad`, `.detach()`/`.item()` ([[2-calculus-and-optimization/autograd|autograd]]).
- Gradient descent finds good parameters but not always exact ones in a fixed number of steps (the fit below ends at $a\approx2.97$, not $3$).

## The computational graph of one data point

![[l06-quadratic-regression-graph.png|Quadratic regression for one data point: parameters a, b, c (purple) feed the model; the squared error is the seed node]]

Nodes: $z_1=x_i$, $z_2=z_1^2$, $z_3=az_2$, $z_4=bz_1$, $z_5=z_3+z_4+c=f(x_i)$, $z_6=y_i$, $z_7=(z_6-z_5)^2=\ell$. Backpropagating from $\bar z_7=1$:

$$
\bar z_5=\bar z_7\frac{\partial z_7}{\partial z_5}=-2(z_6-z_5),\qquad \bar z_3=\bar z_4=\bar c=\bar z_5,
$$

$$
\bar a=\bar z_3\,z_2=-2x_i^2\bigl(y_i-f(x_i)\bigr),\qquad \bar b=\bar z_4\,z_1=-2x_i\bigl(y_i-f(x_i)\bigr),\qquad \bar c=-2\bigl(y_i-f(x_i)\bigr).
$$

($\bar z_1$, $\bar z_2$, $\bar z_6$ are not needed: we only update parameters.) For the whole dataset, average these over $i$ — differentiation is linear.

## In NumPy, with hand-derived gradients

```python
a, b, c = 3, 2, 1                     # "unknown" truth
N = 20
x = np.linspace(-2, 2, N)
y = a*x**2 + b*x + c

a_gd, b_gd, c_gd = np.random.randn(3) # initial guesses
alpha = 3e-2
for n in range(100):
    errors = y - (a_gd*x**2 + b_gd*x + c_gd)
    partial_a = np.sum(-2*x**2*errors)/N   # mean over data
    partial_b = np.sum(-2*x*errors)/N
    partial_c = np.sum(-2*errors)/N
    a_gd -= alpha*partial_a
    b_gd -= alpha*partial_b
    c_gd -= alpha*partial_c
```

```
Initial guesses: a=-1.011118, b=0.202402, c=0.077558
Final guesses: a=2.973337, b=1.999829, c=1.063579
```

## In PyTorch, with autograd

Same problem (lecture uses truth $a=-20$, $b=10$, $c=-3$), but the three partial-derivative lines disappear:

```python
a, b, c = -20, 10, -3                        # new "unknown" truth
x = torch.linspace(-2, 2, N)
y = a*x**2 + b*x + c
a_gd = torch.randn((), requires_grad=True)   # parameters
b_gd = torch.randn((), requires_grad=True)
c_gd = torch.randn((), requires_grad=True)

loss_vals = []
for n in range(100):
    errors = y - (a_gd*x**2 + b_gd*x + c_gd)
    loss = torch.sum(errors**2)/N            # MSE, the seed
    loss.backward()                          # fills .grad
    with torch.no_grad():
        a_gd -= alpha*a_gd.grad              # in-place update
        b_gd -= alpha*b_gd.grad
        c_gd -= alpha*c_gd.grad
        a_gd.grad = None                     # clear gradients
        b_gd.grad = None
        c_gd.grad = None
    loss_vals.append(loss.item())            # plain number
```

```
Initial guesses: a=-2.094469, b=2.089610, c=-0.420542
Final guesses: a=-19.826988, b=9.999246, c=-3.412558
```

The lecture's notes on this code:

- **`requires_grad=True`** on exactly the tensors whose gradients we need — the parameters.
- **`.data.item()`**: `.data` is the values (still a tensor); `.item()` turns a one-element tensor into a Python number.
- **`torch.no_grad()`**: the update must not be recorded in the graph or change the gradients already computed. That is also why the update is `-=` (in place): `a_gd = a_gd - ...` would make a new tensor without `requires_grad`.
- **Setting `.grad = None`**: gradients stay until cleared, and the next `backward()` would add to them.
- **`.detach().numpy()`** before plotting a tensor that is part of a graph (or plot inside `torch.no_grad()`).

All of this boilerplate — listing every parameter, updating and clearing each one — is what [[4-pytorch-training/nn-module|`nn.Module`]] and [[4-pytorch-training/optimizers|`torch.optim`]] remove in Lecture 10.

## Exercise: fitting a sigmoid

The shifted, scaled sigmoid $\tilde\sigma(x)=\dfrac{1}{1+\exp\{-(x-b)/\tau\}}$ has centre $b$ (where $\tilde\sigma=\tfrac12$) and transition width $\tau>0$. Generate noisy data from "unknown" $b=-0.75$, $\tau=2.25$ and recover them by minimizing the MSE over $(b,\tau)$:

```python
x = torch.linspace(-10, 10, 30)
y = 1/(1 + torch.exp(-(x - b)/tau)) + torch.randn_like(x)*0.05  # noise, std 0.05

b_gd = torch.rand((), requires_grad=True)
tau_gd = torch.rand((), requires_grad=True)    # keep tau positive
for n in range(10000):
    outputs = 1/(1 + torch.exp(-(x - b_gd)/tau_gd))
    loss = torch.sum((y - outputs)**2)/len(x)
    loss.backward()
    with torch.no_grad():
        b_gd -= 3e-2*b_gd.grad
        tau_gd -= 3e-2*tau_gd.grad
        b_gd.grad = None
        tau_gd.grad = None
```

```
Initial Guess: b=0.4947, tau=0.8855
Final Guess: b=-0.675175, tau=2.117984
```

The fit is close but not exact because of the added noise. (The exercise text asks for $\alpha=10^{-1}$ and 300 iterations; the solution code above ran $\alpha=3\cdot10^{-2}$ for 10,000. Its comment calls the noise "variance 0.05", but `randn_like(x)*0.05` has standard deviation 0.05.) Unlike the quadratic, this model is **not** linear in its parameters, so its MSE is in general not convex in $(b,\tau)$ — there is no closed form, and gradient descent is the natural tool. (The quadratic, being linear in $a,b,c$, also has a closed-form solution: [[3-linear-models/basis-function-regression|basis-function regression]].)

> [!trap] Common mistakes
> - Sign of the per-example gradient: $\partial(y-f)^2/\partial a=-2x^2(y-f)$, with the minus from the inner derivative.
> - Forgetting $1/N$ in the gradient when the loss is a mean (the step is then $N$ times too large).
> - Initializing $\tau\le0$ in the sigmoid fit: the model divides by $\tau$.
> - Expecting exact recovery: with a fixed number of steps, finite $\alpha$ and noisy data, GD gets close, not exact.
