> [!abstract] In one breath
> Batch norm normalizes every channel's activations to mean 0 and variance 1 using the statistics of the **current batch**, then rescales with two learned numbers per channel: $\mathrm{BN}(z) = \gamma_c\,(z-\mu_c)/\sqrt{\sigma_c^2+\epsilon} + \beta_c$. In **training** it uses batch statistics and updates running averages; in **evaluation** it uses the running averages, so `model.train()` / `model.eval()` matter. It keeps each layer's signal and gradient at a useful scale: training gets faster and much less sensitive to the learning rate.

## What it is

For a batch $z$ of shape $N\times C\times H\times W$ and each channel $c$:

$$
\mu_c = \frac{1}{NHW}\sum_{n,i,j} z_{n c i j},\qquad
\sigma_c^2 = \frac{1}{NHW}\sum_{n,i,j}\big(z_{n c i j}-\mu_c\big)^2,\qquad
\mathrm{BN}(z)_{n c i j} = \gamma_c\,\frac{z_{n c i j}-\mu_c}{\sqrt{\sigma_c^2+\epsilon}} + \beta_c .
$$

The statistics are taken over the batch **and** all pixels (dims 0, 2, 3), separately for each channel. $\gamma_c$ starts at 1 and $\beta_c$ at 0, so a fresh layer outputs standardized activations; training can then learn any scale and shift, including undoing the normalization.

## What you should know

- Per-channel statistics over $(N, H, W)$ for `nn.BatchNorm2d(C)`; over $N$ for `nn.BatchNorm1d(C)` on $N\times C$ features.
- **Learnable parameters: $2C$** ($\gamma$, $\beta$). Plus buffers `running_mean`, `running_var` (and `num_batches_tracked`), which are saved with the model but **not trained**.
- Training mode: normalize with the batch's $\mu_c$ and **biased** $\sigma_c^2$; update running averages with momentum 0.1: $r \leftarrow 0.9\,r + 0.1\cdot(\text{batch value})$, using the **unbiased** variance for `running_var`.
- Evaluation mode: normalize with the running averages; the output no longer depends on the rest of the batch.
- A convolution followed by batch norm needs no bias (`bias=False`): $\beta$ already shifts, and subtracting $\mu_c$ removes any constant.
- Typical order: conv → BN → ReLU ([[5-deep-networks/residual-connections|ResNet]]).
- Lecture 16: plain SGD, 3 epochs: 13.4% → 65.0% (lr 0.02) and 38.7% → 68.3% (lr 0.1) with batch norm.

## Batch norm from scratch

Lecture 16 writes its own module and checks it against [`nn.BatchNorm2d`](https://docs.pytorch.org/docs/stable/generated/torch.nn.BatchNorm2d.html) in both modes:

```python
class MyBatchNorm2d(nn.Module):
    def __init__(self, C, momentum=0.1, eps=1e-5):
        super().__init__()
        self.gamma = nn.Parameter(torch.ones(1, C, 1, 1))
        self.beta = nn.Parameter(torch.zeros(1, C, 1, 1))
        self.register_buffer('running_mean', torch.zeros(1, C, 1, 1))   # saved, not trained
        self.register_buffer('running_var', torch.ones(1, C, 1, 1))
        self.momentum, self.eps = momentum, eps

    def forward(self, x):
        if self.training:                      # this batch, per channel
            mean = x.mean(dim=(0, 2, 3), keepdim=True)
            var = x.var(dim=(0, 2, 3), keepdim=True, unbiased=False)
            with torch.no_grad():
                n = x.numel() / x.shape[1]     # values per channel
                self.running_mean.lerp_(mean, self.momentum)
                self.running_var.lerp_(var * n / (n - 1), self.momentum)
        else:                                  # remembered from training
            mean, var = self.running_mean, self.running_var
        return self.gamma * (x - mean) / torch.sqrt(var + self.eps) + self.beta

torch.manual_seed(0)
ours, torchs = MyBatchNorm2d(8), nn.BatchNorm2d(8)
for _ in range(5):                             # 5 training batches
    batch = 3 * torch.randn(16, 8, 10, 10) + 2
    same_train = torch.allclose(ours(batch), torchs(batch), atol=1e-5)
ours.eval(), torchs.eval()
print('training mode matches nn.BatchNorm2d:  ', same_train)
print('evaluation mode matches nn.BatchNorm2d:', torch.allclose(ours(batch), torchs(batch), atol=1e-5))
print('learnable parameters: {} (= 2C), buffers: {}'.format(
    n_params(torchs), [name for name, _ in torchs.named_buffers()]))
```


- [`nn.Parameter`](https://docs.pytorch.org/docs/stable/generated/torch.nn.parameter.Parameter.html) makes $\gamma,\beta$ show up in `model.parameters()`, so the [[4-pytorch-training/optimizers|optimizer]] trains them.
- [`register_buffer`](https://docs.pytorch.org/docs/stable/generated/torch.nn.Module.html#torch.nn.Module.register_buffer) stores tensors that move with `.to(device)` and are saved in `state_dict()` but are not parameters.
- `self.training` is the flag that `model.train()` and `model.eval()` set ([`nn.Module.train`](https://docs.pytorch.org/docs/stable/generated/torch.nn.Module.html#torch.nn.Module.train)).
- `a.lerp_(b, w)` replaces `a` with $a + w(b-a) = (1-w)\,a + w\,b$ ([`Tensor.lerp_`](https://docs.pytorch.org/docs/stable/generated/torch.Tensor.lerp_.html)).

> [!example] Worked example: one training step
> The batch in the figure, channel 0: values $1,\dots,8$ ($N=2$, $2\times2$ pixels, so 8 values).
> - $\mu_0 = 4.5$, biased $\sigma_0^2 = \frac{1}{8}\sum (v-4.5)^2 = \frac{42}{8} = 5.25$, so $\sqrt{5.25} \approx 2.291$ and the value 1 becomes $(1-4.5)/2.291 \approx -1.53$.
> - With $\gamma_0 = 2$, $\beta_0 = 1$ it would become $2\cdot(-1.53) + 1 = -2.06$.
> - Running statistics (start at mean 0, var 1; momentum 0.1; unbiased variance $\frac{42}{7} = 6$):
>   $\text{running\_mean} = 0.9\cdot 0 + 0.1\cdot 4.5 = 0.45$,
>   $\text{running\_var} = 0.9\cdot 1 + 0.1\cdot 6 = 1.5$.
> - In eval mode right after this one step, the value 1 would be normalized as $(1-0.45)/\sqrt{1.5} \approx 0.45$: very different, because the running averages need many batches to converge.

## Does batch norm help?

The same small CNN with and without `nn.BatchNorm2d` after every convolution, trained with plain [`torch.optim.SGD`](https://docs.pytorch.org/docs/stable/generated/torch.optim.SGD.html) (no momentum, no Adam) for 3 epochs on 20,000 FashionMNIST images, at two learning rates:

```python
def bn_cnn(use_bn):
    def block(c_in, c_out):
        layers = [nn.Conv2d(c_in, c_out, 3, padding=1, bias=not use_bn)]   # beta replaces bias
        if use_bn:
            layers.append(nn.BatchNorm2d(c_out))
        return layers + [nn.ReLU()]
    return nn.Sequential(*block(1, 16), nn.MaxPool2d(2), *block(16, 32), nn.MaxPool2d(2),
                         *block(32, 64), nn.AdaptiveAvgPool2d(1), nn.Flatten(), nn.Linear(64, 10))
```

- Without batch norm, lr 0.02 barely moves the loss in 3 epochs, and lr 0.1 starts slowly.
- With batch norm, both learning rates train quickly and end at similar accuracy: normalizing every layer's activations keeps the signal and its gradient at a useful scale.
- Batch norm is the other half of what makes very deep networks trainable, together with [[5-deep-networks/residual-connections|residual connections]].

> [!trap] Common mistakes
> - Evaluating in training mode: predictions then depend on the other images in the batch, and the running statistics keep changing. Call `model.eval()` before evaluating, `model.train()` before training.
> - Counting $4C$ parameters for `BatchNorm2d(C)`: only $\gamma$ and $\beta$ are trainable ($2C$); the running mean and variance are buffers.
> - Normalizing over the wrong axes: BN2d averages over batch **and** pixels per channel, not over channels per pixel.
> - `nn.BatchNorm1d` in training mode on a batch of a single sample ($1\times C$) raises "Expected more than 1 value per channel when training"; there is nothing to average.
> - Keeping `bias=True` on a convolution right before BN: harmless but wasted parameters.
