> [!abstract] In one breath
> Pooling summarizes each window of a feature map by one number, its **maximum** or its **mean**. Local pooling ($2\times2$, stride 2) halves the map; **global** pooling reduces each whole map to one number. Pooling has **no parameters** (a stride-2 convolution is the learned alternative). The **head** of a CNN turns the last feature maps into class scores: flattening keeps *where* each feature fired, so the classifier breaks when the object moves; **global average pooling** keeps only *how strongly* each feature fired, which turns the convolutions' equivariance into **invariance** with far fewer parameters.

## What it is

A pooling layer slides a window (usually $2\times2$ with stride 2) over each channel **separately** and outputs one number per window:

- **Max pooling** keeps the strongest response: "is the feature present somewhere in this window?"
- **Mean (average) pooling** averages: "how much of the feature is in this window?"
- **Global** pooling uses one window the size of the whole map: a $C\times H\times W$ tensor becomes $C$ numbers. In PyTorch: [`nn.AdaptiveAvgPool2d(1)`](https://docs.pytorch.org/docs/stable/generated/torch.nn.AdaptiveAvgPool2d.html) or [`nn.AdaptiveMaxPool2d(1)`](https://docs.pytorch.org/docs/stable/generated/torch.nn.AdaptiveMaxPool2d.html) (output `(N, C, 1, 1)`), or `x.mean(dim=(2, 3))` / `x.amax(dim=(2, 3))` (output `(N, C)`).

The number of channels never changes. The output size follows the same formula as a convolution, $H_\textrm{out} = \lfloor (H_\textrm{in} + 2p - K)/s\rfloor + 1$, and in [`nn.MaxPool2d`](https://docs.pytorch.org/docs/stable/generated/torch.nn.MaxPool2d.html) the stride defaults to the kernel size, so `nn.MaxPool2d(2)` maps $32\rightarrow16$ and $7\rightarrow3$.

![[l16-maxpoolsample2.png|2x2 max pooling: each colored window keeps its largest value]]

In the lecture's figure the four $2\times2$ windows $\{12, 20, 8, 12\}$, $\{30, 0, 2, 0\}$, $\{34, 70, 112, 100\}$, $\{37, 4, 25, 12\}$ give the maxima $20, 30, 112, 37$. Mean pooling would give $13, 8, 79, 19.5$.

## What you should know

- Max vs mean pooling; local ($2\times2$, stride 2 halves $H$ and $W$) vs global (one number per channel).
- Pooling has **0 parameters** and acts on each channel separately; `nn.MaxPool2d(k)` has stride $k$ by default.
- Compute a pooled map by hand (worked example below), and pooled output sizes with the conv formula.
- Gradients: max pooling sends the whole upstream gradient to the position of the maximum (zero elsewhere); mean pooling over $k\times k$ sends $\frac{1}{k^2}$ of it to every position.
- Convolution is translation **equivariant**; a **global**-pooling head makes the prediction translation **invariant**; a **flatten** head throws that away.
- Head parameter counts: flatten $64\times16\times16 \rightarrow 10$ costs $163{,}850$; GAP then $64\rightarrow10$ costs $650$. With a GAP head the model accepts any input size.

```python
x = torch.tensor([[1., 3., 2., 0.],
                  [4., 6., 1., 1.],
                  [0., 2., 5., 7.],
                  [1., 1., 8., 2.]]).view(1, 1, 4, 4)  # (N, C, H, W)
print('2x2 max pooling:\n', nn.MaxPool2d(2)(x)[0, 0])
print('2x2 mean pooling:\n', nn.AvgPool2d(2)(x)[0, 0])
print('global max: {:.2f}, global mean: {:.2f}'.format(
    nn.AdaptiveMaxPool2d(1)(x).item(), nn.AdaptiveAvgPool2d(1)(x).item()))
print('parameters in a pooling layer:', sum(p.numel() for p in nn.MaxPool2d(2).parameters()))
```

Check: the top-left window $\{1, 3, 4, 6\}$ has max $6$ and mean $14/4 = 3.5$; the 16 entries sum to $44$, so the global mean is $44/16 = 2.75$.

**Gradients.** If the loss gradient arriving at the top-left max-pooled output is $g$, then $\partial L/\partial x = g$ at the entry that held the $6$ and $0$ at the other three; for mean pooling each of the four entries gets $g/4$. On ties, functions differ: `torch.amax` splits the gradient evenly between the tied positions, `nn.AdaptiveMaxPool2d` gives all of it to one ([[5-deep-networks/convolution#learning-the-filter|example]]).

## Global max pooling: "best match anywhere"

In the blob-vs-bar detector of Lecture 15 ([[5-deep-networks/convolution#template-matching-where-is-the-pattern|convolution]]), a $3\times3$ filter followed by **global max pooling** answers "how well does the best window anywhere in the image match?", which is exactly the question when the object can be anywhere. Global *average* pooling would instead dilute one strong match with all the empty background, which suits "how much of this feature is there overall" better. (A free-time question of the lecture: swap `nn.AdaptiveMaxPool2d(1)` for `nn.AdaptiveAvgPool2d(1)` in `train_filter` and see.)

## The head: flatten or global pooling?

After the last convolution the network holds $C$ feature maps of size $H\times W$; the head turns them into class scores.

- **Flatten + FC:** [`nn.Flatten()`](https://docs.pytorch.org/docs/stable/generated/torch.nn.modules.flatten.Flatten.html) then `nn.Linear(C*H*W, n_classes)`. Every feature at every position gets its own weight: position-specific, many parameters, and the input size is fixed.
- **GAP + FC:** `nn.AdaptiveAvgPool2d(1)`, `nn.Flatten()`, then `nn.Linear(C, n_classes)`. Only how strongly each feature fired survives, not where: few parameters and any input size.

```python
def conv_layers(k=3):
    p = k // 2  # 'same' padding, odd k
    return [nn.Conv2d(1, 16, k, padding=p), nn.ReLU(), nn.MaxPool2d(2),   # 64 -> 32
            nn.Conv2d(16, 32, k, padding=p), nn.ReLU(), nn.MaxPool2d(2),  # 32 -> 16
            nn.Conv2d(32, 64, k, padding=p), nn.ReLU()]                   # 64 x 16 x 16

cnn_flatten = nn.Sequential(*conv_layers(), nn.Flatten(), nn.Linear(64*16*16, 10))     # 187,146 params
cnn_gap = nn.Sequential(*conv_layers(), nn.AdaptiveAvgPool2d(1), nn.Flatten(), nn.Linear(64, 10))  # 23,946
```

What happened:

- **MLP:** chance within a few pixels. The object lands on input pixels whose weights it never learned to use (81% of its first-layer pixel weights never changed during training, because those pixels were always zero; see [[5-deep-networks/multilayer-perceptrons#what-an-mlp-cannot-see|MLPs]]).
- **CNN + flatten + FC:** collapses too. The conv layers *do* find the same features after the shift, since convolution is equivariant, but flattening ties each feature to a position the linear layer was never trained on.
- **CNN + GAP + FC:** barely notices. Global pooling keeps how strongly each feature fired and drops where.
- **CNN 5×5 + GAP + FC:** just as flat and more accurate at every shift: a receptive field that covers the whole garment helps, and global pooling still ignores where it is.

The GAP models are less accurate at the training position (78.0% vs 90.2%): only 64 averaged numbers reach the classifier, they learn more slowly (trained for 20 epochs vs 5) and the final training loss stays higher (about 0.58 vs 0.28). The point is the flat shape of the curve, not its height.

> [!definition] Equivariance vs invariance
> For a shift $T$ of the input:
> - $f$ is **translation equivariant** if $f(T x) = T f(x)$: the output moves with the input. Convolutions (and local pooling, for shifts by multiples of the stride) are.
> - $f$ is **translation invariant** if $f(T x) = f(x)$: the output does not change. Global pooling of equivariant feature maps is, so a conv stack + global pooling + linear layer gives (approximately) shift-invariant predictions.
>
> The notebook's Appendix B measures this: it plots each internal feature of one test image at the training position against the same feature with the image shifted by 8 pixels, for the MLP's 256 hidden units and for the CNN's 64 GAP features; a shift-invariant representation puts every point on the diagonal. Shifts that are a multiple of the network's total pooling stride ($2\cdot2 = 4$ pixels) move the final feature maps by whole cells, so the pooled features match almost exactly; other shifts match approximately.

Local $2\times2$ pooling on its own only buys robustness to shifts of a pixel or so; full invariance comes from pooling over the whole map.

## A bonus of global pooling: any input size

Nothing in a conv stack with a global-pooling head depends on $H$ and $W$, so the same model (with the same parameter count) runs on $28\times28$, $64\times64$ or $97\times97$ inputs and always returns `(N, 10)`. The flatten head hard-codes $C\cdot H\cdot W$ in its linear layer, so any other size raises a shape error. Removing the head altogether gives networks whose output is itself an image: [[5-deep-networks/fully-convolutional-networks|fully convolutional networks]].

> [!trap] Common mistakes
> - **Counting parameters for pooling.** There are none; `nn.MaxPool2d(2)` and `nn.AdaptiveAvgPool2d(1)` have nothing to learn.
> - **`nn.AvgPool2d(1)` is not global pooling.** A $1\times1$ window does nothing. Global pooling is `nn.AdaptiveAvgPool2d(1)` (the argument is the *output* size) or `x.mean(dim=(2, 3))`.
> - **Forgetting to flatten after adaptive pooling.** Its output is `(N, C, 1, 1)`; `nn.Linear(C, ...)` needs `(N, C)`: add `nn.Flatten()` or `.flatten(1)`.
> - **Assuming pooling changes the number of channels.** It pools each channel separately.
> - **Stride default.** `nn.MaxPool2d(3)` uses stride 3, not 1; write `nn.MaxPool2d(3, stride=1, padding=1)` to keep the size (as Inception's pooling branch does).
> - **"Convolution makes CNNs shift-invariant."** It makes them equivariant; the head decides whether the prediction is invariant.
