*Lecture 18 · [[7-transformers/index|Transformers]] · builds on [[5-deep-networks/recurrent-neural-networks|recurrent neural networks]] and [[5-deep-networks/lstm-and-gru|LSTM and GRU]]*

> [!abstract] In one breath
> A network needs every input symbol (a letter, a word, a token) as a vector. **One-hot** vectors are simple but as long as the vocabulary; **binary** codes are short but meaningless to the model; **hand-designed** codes are a guess. A **learned embedding** gives every symbol its own trainable vector $e_i\in\mathbb R^d$, stored as the rows of a matrix $E\in\mathbb R^{V\times d}$ and updated by backpropagation like any other weight. In PyTorch this is [`nn.Embedding(V, d)`](https://docs.pytorch.org/docs/stable/generated/torch.nn.Embedding.html): integer indices in, vectors out. On the surname task a learned 8-dimensional embedding beat all three fixed encodings, and the embedding dimension $d$ is a hyperparameter with a sweet spot (about 64 there).

## What it is

Every sequence model so far read one-hot letters: [[5-deep-networks/recurrent-neural-networks|the surname RNN]] turned "Yap" into a $(3, 1, 52)$ tensor with a single 1 in each row. Lecture 18 asks whether that is a good choice, compares three fixed encodings (one-hot, binary, a hand-designed 2-D code), and then lets the network **learn** the representation.

> [!definition] Definition — embedding
> Given a vocabulary of $V$ symbols numbered $0,\dots,V-1$, an **embedding** assigns symbol $i$ a vector $e_i\in\mathbb R^d$. Stacking them gives the **embedding matrix** $E\in\mathbb R^{V\times d}$ (row $i$ is $e_i$). A **learned** embedding treats $E$ as parameters: the loss gradient flows back through the model into the rows that were used, and the optimizer updates them. The **embedding dimension** $d$ is chosen independently of $V$.

## What you should know

- The four Lecture 18 encodings, their input dimension for 52 letters (one-hot 52, binary $\lceil\log_2 52\rceil = 6$, custom 2-D, learned $d$), and how they ranked on held-out names.
- `nn.Embedding(num_embeddings=V, embedding_dim=d)`: weight shape $(V, d)$, $V\cdot d$ parameters, input an **integer** tensor of any shape $S$, output shape $(*S, d)$.
- An embedding lookup equals a one-hot vector times $E$: $\text{onehot}(i)^\top E = e_i$. So a linear layer on one-hot inputs already learns one vector per symbol; the embedding layer just skips the multiplication.
- Only the rows of symbols that appear in a batch get a nonzero gradient.
- Why $d$ decouples the input size from the vocabulary size, and the trade-off in choosing $d$: too small loses information, too large costs compute and parameters for no gain (the sweep peaks around $d=64$ and dips beyond 256).
- Nearby embeddings can be found with Euclidean distance ([`torch.cdist`](https://docs.pytorch.org/docs/stable/generated/torch.cdist.html)); after training, symbols used alike tend to sit close together.

## Four encodings of the same letters

The data is the surname set from Lecture 17, cut to the eight languages with 200–800 names each (Chinese, Czech, Dutch, French, German, Irish, Italian, Spanish), split 50/50 into training and validation. Letters are indexed by `string.ascii_letters`: `a`–`z` are 0–25 and `A`–`Z` are 26–51.

| Encoding | Vector for one letter | Size $d$ | Example from the notebook |
| --- | --- | --- | --- |
| One-hot | $1$ at the letter's index, $0$ elsewhere | 52 | "Yap": 1s at positions 50 (`Y`), 0 (`a`), 15 (`p`) |
| Binary | the index written in 6 bits | 6 | "Parri": `P` = 41 = `101001`, `a` = 0 = `000000`, `r` = 17 = `010001`, `i` = 8 = `001000` |
| Custom 2-D | $x_1=-1$ lowercase / $+1$ uppercase; $x_2$ = alphabet position mapped linearly to $[-1,1]$ ($a=-1$, $z=+1$) | 2 | "Semick": `S` → $(1, 0.44)$, `e` → $(-1,-0.68)$, `m` → $(-1,-0.04)$ |
| Learned | row $i$ of a trainable $52\times d$ matrix | $d$ (8 here) | "Campo": indices `[28, 0, 12, 15, 14]` |

The 2-D value is $x_2 = 2\cdot\frac{\text{index of the lowercase letter}}{25}-1$, so `s` (18) gives $2\cdot 18/25 - 1 = 0.44$ and `e` (4) gives $-0.68$.

The dataset class builds each one in a few lines; the binary and 2-D helpers:

```python
def letter_to_binary(self, letter, n_bits):
    index = self.letter_to_index(letter)
    binary_string = bin(index).split('b')[1]   # drop the '0b'
    tensor = torch.zeros(n_bits)
    for i in range(len(binary_string)):        # LSB to MSB
        j = -(i+1)
        tensor[j] = int(binary_string[j])
    return tensor.float()

def letter_to_2d(self, letter):
    index = self.letter_to_index(letter)
    tensor = torch.zeros(2)
    tensor[0] = -1 if index <= 25 else 1       # lowercase vs uppercase
    tensor[1] = 2*(self.letter_to_index(letter.lower())/25) - 1
    return tensor
```

The same `ElmanRNN` (128 hidden units, one layer, [`nn.CrossEntropyLoss`](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html), [SGD](https://docs.pytorch.org/docs/stable/generated/torch.optim.SGD.html) with `lr=3e-3`, `momentum=0.99`, 100 epochs) was trained on each; only `input_dim` changes (the learned case puts an `nn.Embedding` in front, see below).

> [!intuition] Why binary loses to one-hot, and 2-D loses to both
> The lecture's explanation: with one-hot input the model reads **one** entry to know the letter; with a binary code it must "listen" to all six bits and combine them, so the network "works harder" for the same information. Beyond what the lecture says: codes that look alike mean nothing alike: `r` = `010001` and `b` = `000001` differ in one bit. The custom 2-D code is worse still: it forces an ordering on the alphabet (`m` sits halfway between `a` and `z`) that has nothing to do with which language a name comes from, and it squeezes 52 letters into two numbers. Compactness alone does not help; the representation has to be **useful for the task**.

## Learning the embedding

Instead of designing a code, let gradient descent choose it. [`nn.Embedding`](https://docs.pytorch.org/docs/stable/generated/torch.nn.Embedding.html) is a lookup table: its `weight` is a $(V, d)$ [`Parameter`](https://docs.pytorch.org/docs/stable/generated/torch.nn.parameter.Parameter.html), initialized from $\mathcal N(0,1)$, and `embedding(x)` returns `weight[x]`.

The lecture's model puts the embedding in front of the same RNN (the notebook's text says $d = 64$, but its code and printed results use `embedding_dim = 8`):

```python
class EmbeddingRNN(nn.Module):
    def __init__(self, num_embeddings, embedding_dim, hidden_dim, output_dim, n_layers, bidirectional):
        super(EmbeddingRNN, self).__init__()
        self.n_layers = n_layers
        self.hidden_dim = hidden_dim
        self.bidirectional = bidirectional
        self.embedding = nn.Embedding(num_embeddings, embedding_dim)
        self.rnn = nn.RNN(embedding_dim, hidden_dim, n_layers, nonlinearity='tanh',
                          bidirectional=bidirectional, batch_first=False)
        self.D = 2 if bidirectional else 1
        self.fc = nn.Linear(self.D*hidden_dim, output_dim)

    def forward(self, x):
        h0 = torch.zeros(self.D*self.n_layers, x.size(1), self.hidden_dim).to(DEVICE)
        z = self.embedding(x)                   # (L, 1) ints -> (L, 1, d)
        outputs, hiddens = self.rnn(z, h0)
        if self.bidirectional:
            y = (self.fc(outputs[-1])+self.fc(outputs[0]))/2
        else:
            y = self.fc(outputs[-1])
        return [y], hiddens
```

### Shapes and parameters

| Tensor | Shape | Notes |
| --- | --- | --- |
| input `x` | $(L, 1)$ | integer dtype (`int32` or `int64`); a float tensor is an error |
| `embedding.weight` | $(V, d) = (52, 8)$ | $V\cdot d = 416$ parameters |
| `z = embedding(x)` | $(L, 1, d)$ | a new last dimension of size $d$ is appended |
| RNN input | $(L, N, d)$ with `batch_first=False` | here $N = 1$ |

`nn.Embedding` takes an index tensor of **any** shape $S$ and returns shape $(*S, d)$: a $(B, L)$ batch of token ids gives $(B, L, d)$.

### An embedding is a one-hot vector times a matrix

For a one-hot column $u_i\in\{0,1\}^V$ with its 1 at position $i$,

$$
u_i^\top E = e_i \quad(\text{row } i \text{ of } E),\qquad W u_i = w_{:,i}\quad(\text{column } i \text{ of } W).
$$

So the one-hot RNN's input weights $W_{ih}\in\mathbb R^{128\times 52}$ already hold one learned 128-dimensional vector per letter; the embedding layer computes the same kind of lookup without multiplying by a mostly-zero vector, and with an embedding the RNN's effective input matrix is $W_{ih}E^\top\in\mathbb R^{128\times V}$ — a product of rank at most $d$ (since $e_i = E^\top u_i$). The practical advantages are that the lookup is cheap for large $V$ (no $V$-long one-hot vectors) and that $d$ is free to choose. The lecture's single runs put the learned $d = 8$ embedding ahead of one-hot (58.9% vs 53.1%), but each run also draws its own random split: in the sweep below the $d = 8$ average is $55.9 \pm 1.0$, so the advantage over one-hot at $d=8$ is a few points; it grows to about 10 points at $d = 64$.

### Gradients reach only the rows that were used

The loss depends on $E$ only through the rows looked up, so $\partial \mathcal L/\partial e_j = 0$ for every symbol $j$ that is not in the batch. For "Campo", only rows 0, 12, 14, 15 and 28 change from that example (a row used twice accumulates both gradients). A letter that never appears in training keeps its random initial vector (absent weight decay).

## Choosing the embedding dimension

$d = 8$ was arbitrary. The lecture trained the surname model for $d\in\{1,2,4,\dots,1024\}$, three runs each, and saved the results.

## Finding nearby embeddings

Once trained, distances between rows of $E$ say which symbols the model treats alike. The lecture's bonus code (on the word embeddings of [[7-transformers/tokenization|the sentiment model]]):

```python
embedding_matrix = embedding_rnn_model.embedding.weight.detach()
K = 10
test_word = 'yes'
embedding_idx = sentiment_dataset.word_to_idx[test_word]
embedding_distances = torch.cdist(embedding_matrix, embedding_matrix[embedding_idx].unsqueeze(0))  # (V, 1)
best_indices = torch.argsort(embedding_distances.view(-1))[1:K+1]  # skip the word itself
for k in range(K):
    print(sentiment_dataset.idx_to_word[best_indices[k].item()])
```

[`torch.cdist`](https://docs.pytorch.org/docs/stable/generated/torch.cdist.html) of a $(V, d)$ and a $(1, d)$ tensor gives the $(V, 1)$ Euclidean distances; [`torch.argsort`](https://docs.pytorch.org/docs/stable/generated/torch.argsort.html) orders them, and index 0 of the result is the word itself (distance 0), so it is skipped. Embeddings trained for one task only cluster what that task needs: a sentiment model has reason to put "great" near "excellent", not "great" near "big". (The notebook saves no output for this cell.)

> [!trap] Common mistakes
> - **Feeding floats to `nn.Embedding`.** The input must be an integer index tensor (`long` or `int`); the one-hot or float encodings of the earlier sections are for `nn.RNN` directly, not for an embedding.
> - **Index out of range.** Indices must lie in $0,\dots,V-1$; an unknown word with no index (or index $V$) raises an error. The sentiment dataset avoids this by dropping titles with out-of-vocabulary words.
> - **Forgetting the new dimension.** `embedding(x)` has one more dimension than `x`: $(L, 1)\to(L, 1, d)$. Pass `embedding_dim` as the RNN's `input_size`.
> - **Reading the training curve.** All encodings reach ≈98% on training names; compare encodings and embedding sizes on **validation** accuracy.
> - **Assuming an ordering means something.** Hand-designed codes (the 2-D one, or any integer used directly as a feature) impose a geometry the task may not have.

> [!question]- Check yourself
> 1. How many parameters does `nn.Embedding(10000, 300)` have, and what is the output shape for input token ids of shape `(32, 20)`?
> 2. A one-hot RNN with 52 inputs and 128 hidden units, and an embedding RNN with $d = 52$: which has more parameters, and by how much?
> 3. After one training step on the single name "Anna", which rows of a $52\times d$ letter embedding have changed (plain SGD, no weight decay)?
>
> > [!solution]- Answers
> > 1. $10{,}000\cdot300 = 3{,}000{,}000$ parameters; output `(32, 20, 300)`.
> > 2. The embedding RNN, by exactly the embedding table: $52\cdot52 = 2{,}704$ more. Both have $W_{ih}\in\mathbb R^{128\times52}$; the embedding version also has $E\in\mathbb R^{52\times52}$.
> > 3. Rows 26 (`A`), 13 (`n`) and 0 (`a`); row 13 accumulates the gradients of both `n`s. With momentum, rows that received gradients in earlier steps keep moving too.
