*Lecture 21 · [[7-transformers/index|Transformers]] · builds on [[7-transformers/text-classification-with-transformers|text classification with a `<CLS>` token]] and [[7-transformers/pytorch-transformer-layers|PyTorch's Transformer layers]] · compare [[5-deep-networks/convolutional-layers|convolutional layers]]*

> [!abstract] In one breath
> A Transformer encoder works on any input you can turn into a sequence of vectors. The **Vision Transformer (ViT)** makes an image into such a sequence by cutting it into non-overlapping $P \times P$ **patches**, flattening each patch into a vector of $3P^2$ numbers, and passing every patch through the same linear layer. Add a learned position vector to each, put a learned `<CLS>` vector in front, run encoder layers, and classify from the `<CLS>` output: the text classifier, with patches for words. A $160\times160$ image with $P = 16$ becomes $10\times10 = 100$ patch tokens plus one.

## What it is

The method comes from the paper *An Image Is Worth 16x16 Words: Transformers for Image Recognition at Scale* (Dosovitskiy et al.), whose figure the lecture shows:

![[l21-vit.png|The Vision Transformer (figure from Dosovitskiy et al., shown in Lecture 21): patches are flattened, linearly projected, given position embeddings and a class token, encoded, and classified by an MLP head]]

Reading the figure from the bottom: the image is tiled into patches; the patches are laid out in **raster order** (left to right, one row of patches at a time); a single linear layer projects each flattened patch; the pink/purple pairs are patch embedding plus position embedding; token 0 with the star is the extra learnable class embedding; and only that token's output reaches the MLP head.

## What you should know

- **Tokens.** An $H\times W$ image with patch size $P$ and stride $P$ gives $(H/P)\cdot(W/P)$ patch tokens, plus 1 for `<CLS>`. Each flattened patch has $C\cdot P^2$ numbers ($3P^2$ for RGB).
- **Patch embedding.** One `nn.Linear` applied to every patch. It does for patches what [`nn.Embedding`](https://docs.pytorch.org/docs/stable/generated/torch.nn.Embedding.html) does for word indices; pixel values cannot index a table, so a projection replaces the lookup.
- **Positions.** A learned embedding indexed by the patch's place in raster order. Without it the model would not know where a patch came from ([[7-transformers/positional-encoding#attention-does-not-see-order|attention ignores order]]).
- **Prediction.** From the `<CLS>` output, through a small MLP (the paper's choice) or a linear layer.
- **Why not pixels as tokens?** A $160\times160$ image would be 25,600 tokens and attention would need about $6.6\times10^8$ weights per head per layer.
- **Global from layer 1.** Self-attention relates any two patches in the first layer; a convolution only relates pixels inside one kernel window.
- **Input size.** The encoder layers accept any number of tokens, so a ViT can process a larger image without new layers (it needs enough position embeddings). An MLP's first layer is tied to one input size.
- The lecture's code: `nn.Unfold` to cut patches, `d_emb = 3 * token_size**2`, 2 layers, 8 heads, learning rate $10^{-4}$.

## From the lecture

*From the class recording, paraphrased.*

- With text the first step is tokenizing. For images the whole question is what a token should be; once that is answered the rest of the Transformer is unchanged.
- A token per pixel would be "extremely wasteful and extremely expensive" (Nov 5), so the image is tiled into patches instead, with stride equal to the patch size.
- You cannot use pixel values as keys into a dictionary of vectors the way word indices are used. A learnable linear projection, the same weight matrix for every patch, stands in for the embedding table. On Nov 10 he added that this is meant to emulate the embedding vocabulary and should not be read as rich feature learning by itself.
- The integers in the paper's figure are indices into a learnable positional embedding of the same length as the projected patches.
- The class token works exactly as in [[7-transformers/text-classification-with-transformers|text classification]]; the paper predicts from it with a two-layer MLP (one hidden layer).
- This is the first model in several lectures that is fed real batches. Images can be cropped to one size, so batching is easy, and the training loop is "back to being really simple" (Nov 5): loop over a `DataLoader`, zero the gradients, forward, loss, backward, step.
- The class-embedding module has a vocabulary of size one. It exists only to hold the single learnable `<CLS>` vector.
- The Vision Transformer needed a much lower learning rate than the course's usual values: $10^{-4}$. At $10^{-2}$ it failed to learn and stayed at random predictions.
- Judge results against the guessing baseline (four balanced classes: 25%). After 50 epochs the model is clearly above it, a gap between training and validation accuracy is opening, and the loss is still falling, so it should be trained longer.
- ImageWoof is hard on purpose: ten similar dog breeds, and photos with distractors (people share eyes, noses and mouths with dogs).
- Preload the images in the data set's constructor. Opening files inside `__getitem__` makes every epoch slow.
- CNN or Vision Transformer? He described the choice as task- and data-dependent, with "a lot of back and forth" in computer vision, and suggested comparing them and varying the patch size and the amount of training data.

> [!tip] Shortcut — counting tokens
> Patches per side $= \text{side}/P$; tokens $=$ (patches per side)$^2$, plus 1 if there is a class token; length of a flattened patch $= 3P^2$.
>
> Lecture example: $160/16 = 10$ per side, so a $10\times10$ grid of 100 patches (101 tokens), each $3\cdot16\cdot16 = 768$ long. Exam example ([[9-midterm-2/fall-2025#problem-5--mlp-cnn-or-vision-transformer-23-pts|Fall 2025 Q5]]): $64/8 = 8$ per side, 64 tokens of length $3\cdot8\cdot8 = 192$.

> [!intuition] Analogy — patches are the words of an image
> A sentence is a row of word tokens; an image becomes a row of patch tokens. The linear projection is the patch's "embedding lookup", the position embedding says where in the picture the patch sat, and from there the model cannot tell it is not reading text.

## Tokenizing an image by hand

Take a one-channel $4\times8$ image and $2\times2$ patches (the set-up of Homework 6, Problem 2(d)):

$$
x=\begin{bmatrix}7&7&0&4&3&3&1&3\\8&3&5&4&6&1&9&2\\5&6&2&5&1&7&1&6\\8&9&8&6&6&1&5&3\end{bmatrix}
$$

There are $(4/2)\cdot(8/2) = 2\cdot4 = 8$ patches. Reading patches in raster order, and the entries inside each patch row by row:

| Token | Patch (rows, columns) | Flattened |
| --- | --- | --- |
| 1 | rows 0–1, cols 0–1 | $(7, 7, 8, 3)$ |
| 2 | rows 0–1, cols 2–3 | $(0, 4, 5, 4)$ |
| 3 | rows 0–1, cols 4–5 | $(3, 3, 6, 1)$ |
| 4 | rows 0–1, cols 6–7 | $(1, 3, 9, 2)$ |
| 5 | rows 2–3, cols 0–1 | $(5, 6, 8, 9)$ |
| 6 | rows 2–3, cols 2–3 | $(2, 5, 8, 6)$ |
| 7 | rows 2–3, cols 4–5 | $(1, 7, 6, 1)$ |
| 8 | rows 2–3, cols 6–7 | $(1, 6, 5, 3)$ |

Eight tokens of length $1\cdot2\cdot2 = 4$. With three colour channels each token would be 12 long: [`nn.Unfold`](https://docs.pytorch.org/docs/stable/generated/torch.nn.Unfold.html) lists all of channel 0's patch entries, then channel 1's, then channel 2's.

The patch size is the Vision Transformer's version of the [[7-transformers/tokenization#token-size-against-vocabulary-size|token-size question]] for text. Small patches keep fine detail but make the sequence long, and attention cost grows with the **square** of the number of tokens ([[7-transformers/attention#cost|cost of attention]]). Large patches are cheap but each token blurs a big region into one vector.

## The lecture's implementation

```python
class ViTPositionalEncoding(nn.Module):
    def __init__(self, embedding_dim):
        super(ViTPositionalEncoding, self).__init__()
        self.embedding = nn.Embedding(10**4, embedding_dim)

    def forward(self, x):                       # x: (B, n_tokens, d_emb)
        p = torch.arange(x.size(1)).to(DEVICE)  # 0 .. n_tokens-1
        return self.embedding(p).float()        # (n_tokens, d_emb)

class VisionTransformer(nn.Module):
    def __init__(self, n_layers, n_head, n_classes, token_size, dropout=0.1):
        super(VisionTransformer, self).__init__()
        d_emb = 3*token_size**2
        d_ff = 2*d_emb
        self.token_size = token_size
        self.cls_embedding = nn.Embedding(1, d_emb)                 # one learned vector
        self.tokenizer = nn.Unfold(token_size, stride=token_size)   # non-overlapping patches
        self.positional_encoding = ViTPositionalEncoding(d_emb)
        self.patch_projector = nn.Linear(d_emb, d_emb)
        self.encoder_layers = nn.ModuleList([nn.TransformerEncoderLayer(d_emb, n_head, d_ff,
                                                                        dropout=dropout,
                                                                        batch_first=True)
                                             for n in range(n_layers)])
        self.fc_predict = nn.Sequential(nn.Linear(d_emb, d_ff),
                                        nn.ReLU(),
                                        nn.Linear(d_ff, n_classes))

    def tokenize_image(self, x):
        H, W = x.size(-2), x.size(-1)
        pad_right = W % self.token_size
        pad_bottom = H % self.token_size
        padded_image = F.pad(x, (0, pad_right, 0, pad_bottom), mode='constant', value=0)
        return self.tokenizer(padded_image).permute(0, 2, 1)

    def forward(self, x):
        B = x.size(0)
        z = self.tokenize_image(x)                    # (B, N_patches, d_emb)
        z = self.patch_projector(z)                   # (B, N_patches, d_emb)
        cls_tokens = torch.zeros((B, 1), device=DEVICE).long()
        cls_embed = self.cls_embedding(cls_tokens)    # (B, 1, d_emb)
        z = torch.cat((cls_embed, z), dim=1)          # (B, N_patches+1, d_emb)
        z = z + self.positional_encoding(z)
        for layer in self.encoder_layers:
            z = layer(z)
        preds = self.fc_predict(z[:, 0])              # <CLS> output, (B, d_emb)
        return preds
```

Shape trace for a batch of 8 crops of $160\times160$ with `token_size = 16`:

| Step | Shape | Note |
| --- | --- | --- |
| input `x` | `(8, 3, 160, 160)` | |
| `self.tokenizer(...)` | `(8, 768, 100)` | `nn.Unfold` returns `(B, C·P·P, L)` with $L = 100$ patches |
| `.permute(0, 2, 1)` | `(8, 100, 768)` | tokens on axis 1, as `batch_first=True` expects |
| `patch_projector` | `(8, 100, 768)` | the same `Linear(768, 768)` for every patch |
| `torch.cat((cls_embed, z), dim=1)` | `(8, 101, 768)` | `<CLS>` goes in front |
| `+ positional_encoding(z)` | `(8, 101, 768)` | `(101, 768)` broadcast over the batch |
| encoder layers | `(8, 101, 768)` | each of the 8 heads is $768/8 = 96$ wide |
| `z[:, 0]` | `(8, 768)` | one vector per image |
| `fc_predict` | `(8, 4)` | logits for 4 breeds |

- [`nn.Unfold(kernel_size, stride)`](https://docs.pytorch.org/docs/stable/generated/torch.nn.Unfold.html) slides a window over the image and returns each window flattened into a column. With `stride == kernel_size` the windows do not overlap: a tiling.
- `nn.Embedding(1, d_emb)` is a table with one row. Looking up index 0 for every image returns the same learnable `<CLS>` vector, `B` times.
- The model's width is tied to the patch size here (`d_emb = 3P²`), so `patch_projector` is square. In the paper the projection maps $3P^2$ numbers to a freely chosen width.
- [`F.pad`](https://docs.pytorch.org/docs/stable/generated/torch.nn.functional.pad.html) with `(0, pad_right, 0, pad_bottom)` adds zeros on the right and bottom only.

> [!warning] The padding amount in `tokenize_image`
> The code pads by `W % token_size`, the **remainder** $r$. Reaching the next multiple of the patch size needs `(-W) % token_size` $= P - r$ instead. For the lecture's $160\times160$ training crops $r = 0$, so nothing is padded, as the lecturer said. Otherwise `nn.Unfold` keeps $\lfloor (W + r)/P\rfloor$ patches per row:
> - width 170, $P = 16$ ($r = 10$): padded to 180, 11 patches cover 176 columns, so the whole image is kept (with 6 columns of zeros);
> - width 165 ($r = 5$): padded to 170, only 10 patches fit, and the last 5 **real** columns are dropped.
>
> So remainders below $P/2$ lose a thin strip on the right and bottom of full-size evaluation images. It does not affect training, and the effect on accuracy is small, but the padding does not do what its name suggests.

### Parameters

| Part | Parameters |
| --- | --- |
| `cls_embedding`, $1\times768$ | 768 |
| position table, $10^4\times768$ | 7,680,000 |
| `patch_projector`, $768\cdot768 + 768$ | 590,592 |
| 2 encoder layers, $8\cdot768^2 + 11\cdot768 = 4{,}727{,}040$ each | 9,454,080 |
| head: `Linear(768, 1536)` + `Linear(1536, 4)` | $1{,}181{,}184 + 6{,}148 = 1{,}187{,}332$ |
| **total** | **18,912,772** |

The position table is sized for up to 10,000 tokens; a $160\times160$ crop uses 101 rows ($77{,}568$ parameters). Without the unused rows the model has about 11.3 million parameters. (Derived from the layer definitions; see `tools/verify_mt2.py`.)

## The experiment: ImageWoof

**Data.** ImageWoof is a subset of ImageNet with ten dog breeds (beagle, dingo, golden retriever, Samoyed, and so on), roughly a thousand training images per breed, resized so the shorter side is 160 pixels. The lecture's `DoggieDataset` loads the first `n_classes = 4` breed folders, converts each image to a tensor, and normalizes with the ImageNet channel means and standard deviations. Half of the loaded training images are used for training, the other half for validation.

**Batching.** Images have different sizes (for example $160\times240$). In training mode `__getitem__` applies `RandomCrop((160, 160))`, so every item has the same shape and a `DataLoader` can stack them. For evaluation the full image is used, one image at a time (`model(image.unsqueeze(0))`): a $160\times240$ image simply becomes $10\times15 + 1 = 151$ tokens. That the same weights handle both is the input-size flexibility in action.

**Settings and training loop.**

```python
vit = VisionTransformer(n_layers=2, n_head=8, n_classes=4, token_size=16, dropout=0.2).to(DEVICE)
train_loader = DataLoader(train_dataset, batch_size=8, shuffle=True)
optimizer = torch.optim.SGD(vit.parameters(), lr=1e-4, momentum=0.99)

for i in tqdm(range(n_epochs)):                # n_epochs = 50
    model.train()
    for images, labels in train_loader:
        optimizer.zero_grad()
        images, labels = images.to(DEVICE), labels.to(DEVICE)
        preds = model(images)
        loss = criterion(preds, labels)        # nn.CrossEntropyLoss
        loss.backward()
        optimizer.step()
    model.eval()                               # dropout off for accuracy
```

This is the plain [[4-pytorch-training/training-loop|training loop]] of Lecture 11 again. Accuracy is measured after each epoch on 400 random images from each split.

**Results** (read off the notebook's plot; 50 epochs took about 6 minutes on a GPU): the training loss falls steadily from about 1.4 to 0.8 and has not flattened; training accuracy climbs to about 0.55 and validation accuracy to between 0.42 and 0.49, against a guessing baseline of 0.25. The curves are noisy because each point uses 400 images. By the criteria of [[4-pytorch-training/underfitting-and-overfitting|Lecture 22]] this run is still underfitted (training accuracy far from perfect, loss still falling), with a generalization gap beginning to open.

## MLP, CNN or Vision Transformer?

For an RGB image of size $(3, H, W)$:

| | MLP | CNN | Vision Transformer |
| --- | --- | --- | --- |
| Input to the first layer | all $3HW$ pixels, flattened | the image, kept as a grid | patches as a sequence of tokens |
| What one first-layer output sees | every pixel | a $K\times K$ neighbourhood | every patch, through attention |
| Top-left and bottom-right pixels interact in layer 1? | **yes** | **no** (not until the [[5-deep-networks/convolutional-layers#receptive-field|receptive field]] covers both) | **yes** |
| First-layer parameters depend on image size? | **yes**: `Linear(3·H·W, …)` | no: $C_{out}(C_{in}K^2 + 1)$ | no |
| New image size without a new model? | **no** | yes, with [[5-deep-networks/pooling#a-bonus-of-global-pooling-any-input-size|global pooling]] before the classifier | yes: more tokens (needs position embeddings for them) |
| Built-in assumptions | none | locality and [[5-deep-networks/convolution#one-filter-applied-everywhere|weight sharing across positions]] | weights shared across patches; order only through position embeddings |

Numbers for $(3, 64, 64)$, the case of [[9-midterm-2/fall-2025#problem-5--mlp-cnn-or-vision-transformer-23-pts|Fall 2025 Problem 5]]: the MLP's first layer `nn.Linear(3*64*64, 512)` has $12{,}288\cdot512 + 512 = 6{,}291{,}968$ parameters and cannot take a $(3, 128, 128)$ image, which flattens to 49,152 numbers. A ViT with $8\times8$ patches sees 64 tokens of length 192 at $64\times64$ and 256 tokens at $128\times128$.

A CNN's assumptions (nearby pixels belong together; a pattern means the same thing wherever it appears) are true of photographs, which is why CNNs learn well from modest amounts of data. A ViT has to learn such regularities from examples. The ViT paper reports the consequence: trained on mid-sized data sets its models fell short of comparable ResNets, and they pulled ahead only after pre-training on much larger ones. The lecture leaves the comparison open and suggests trying both.

> [!trap] Common mistakes
> - **Forgetting the `+1`.** $N$ patches plus the class token is $N + 1$ tokens; the position table needs a row for each.
> - **Token length without the channels.** A flattened RGB patch is $3P^2$ long, not $P^2$.
> - **Overlapping patches.** The stride equals the patch size. With a smaller stride `nn.Unfold` returns overlapping windows and many more tokens.
> - **Wrong axis order after `nn.Unfold`.** It returns `(B, C·P·P, L)`; the encoder wants `(B, L, d)`. Hence the `permute`.
> - **`n_head` must divide `d_emb`.** $768/8 = 96$ works; with $P = 8$ the width is 192, so 8 heads still work but 5 would not.
> - **A learning rate copied from other models.** $10^{-2}$ did not train this model; $10^{-4}$ did.
