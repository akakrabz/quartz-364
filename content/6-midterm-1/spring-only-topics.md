## SVM margins

A linear SVM picks the boundary $w^\top x+b=0$ with the **widest margin**. The margin lines are $w^\top x+b=\pm1$, a distance $2/\Vert w\Vert$ apart. **Support vectors** are the training points on the margin lines; removing any *other* point leaves the boundary unchanged, while removing a support vector can move it.

The soft-margin loss trades margin against violations:
$$
L=\min_{w,\xi}\ \frac12\Vert w\Vert_2^2+C\sum_{i=1}^n\xi_i.
$$
Smaller $C$ makes violations cheap: a wider margin and more training errors, possibly better test accuracy on noisy data. As $C\to0$, $w\to0$.

| exam | boundary | margins | support vectors |
|---|---|---|---|
| Spring 2025 Q4 | $y=x$ | $y=x\pm1$ | X: $(2,3),(3,4),(6,7)$ · O: $(3,2),(4,3),(8,7)$ |
| Spring 2026 Q5(a) | $y=x$ | $y=x\pm1$ | X: $(2,3),(3,4)$ · O: $(4,3),(8,7)$ |
| Spring 2026 Q5(b), remove $(8,7)$ | unchanged | unchanged | $(4,3)$ still holds the O margin |
| Spring 2026 Q5(c), remove $(2,3),(3,4)$ | $y=x+1$ (toward the X's) | $y=x+3$, $y=x-1$ | X: $(1,4),(4,7)$ · O: $(4,3),(8,7)$ |

## Linear classifiers for logic tables

Find $(w,b)$ so that $\operatorname{sign}(w\cdot x+b)$ matches every row, with $\operatorname{sign}(0)=+1$. Write one inequality per row and try small integers: the negative rows want $w\cdot x+b<0$, the positive rows $\ge0$.

- **IMPLICATION** on $\{\pm1\}^2$ (Spring 2025 Q5): $w=(-1,1)$, $b=1$ gives $w\cdot x+b=1,3,-1,1$ for $(+,+),(-,+),(+,-),(-,-)$: signs $+,+,-,+$ ✓.
- **Three inputs** (Spring 2026 Q6): $w=(-1,1,0)$, $b=1$ gives $1,3,1,-1$ ✓ — the third input is irrelevant.

A logic table is linearly separable only if some line splits its $+$ rows from its $-$ rows; XOR is the classic table that no single linear classifier can match, which is why [[5-deep-networks/multilayer-perceptrons|multilayer perceptrons]] exist.

## nn.Module, Dataset and DataLoader

- **`nn.Module`.** Subclass it, call `super().__init__()`, register parameters with `nn.Parameter` or layers such as `nn.Linear`, and implement `forward(self, x)`. `model(x)` calls `forward`; `model.parameters()` collects every parameter. → [[4-pytorch-training/nn-module|nn.Module]]
- **`Dataset`** implements `__init__`, `__len__` and `__getitem__(i)` returning `(x, y)`. **`DataLoader(dataset, batch_size, shuffle, sampler)`** serves batches; `SubsetRandomSampler(indices)` restricts it to one split. → [[4-pytorch-training/datasets-and-dataloaders|datasets and DataLoaders]]
- **Training-loop order:** `zero_grad` → forward → loss → `backward` → `step`. → [[4-pytorch-training/training-loop|training loop]]
- **Momentum and weight decay** (L10): $G^{(k)}=g^{(k)}+\mu G^{(k-1)}$, $\theta^{(k+1)}=\theta^{(k)}-\alpha G^{(k)}$. Weight decay adds $\lambda\theta$ to the gradient: the same L2 penalty as [[3-linear-models/ridge-regression|ridge]]. → [[4-pytorch-training/optimizers|optimizers]]
- **Splits** (L11): train fits the weights, validation tunes hyperparameters, test is used once for the final evaluation. → [[4-pytorch-training/experimental-setup|experimental setup]]

```python
class HomePriceModel(nn.Module):           # Spring 2026 Q8
    def __init__(self, num_features):
        super().__init__()
        self.w = nn.Parameter(torch.ones(num_features))
        self.b = nn.Parameter(torch.zeros(1))

    def forward(self, x):                  # x: (B, 3)
        return x @ self.w + self.b         # (B,)
```
