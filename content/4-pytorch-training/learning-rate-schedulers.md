*Lecture 10 · [[4-pytorch-training/index|PyTorch training]] · builds on [[4-pytorch-training/optimizers|optimizers]] and [[2-calculus-and-optimization/gradient-descent|step size in gradient descent]]*

> [!abstract] In one breath
> A large learning rate makes fast progress early but bounces around the minimum late; a small one is precise but slow. So in practice the rate is **lowered during training**, most simply by a factor (e.g. 10×) whenever the loss or validation accuracy plateaus. A scheduler from [`torch.optim.lr_scheduler`](https://docs.pytorch.org/docs/stable/optim.html#how-to-adjust-learning-rate) wraps the optimizer and changes its `lr` each time you call `scheduler.step()` — usually once per epoch, after the epoch's `optimizer.step()` calls.

## What it is

Lecture 10 only introduces the idea ("we will not worry about these for now"): after the loss plateaus, a smaller learning rate lets gradient descent settle more carefully into the minimum it is already in and squeeze out a little more performance. The [[2-calculus-and-optimization/gradient-descent|gradient-descent]] picture explains why: with step $\alpha$ the iterates near a minimum of curvature $c$ jump by a factor $1-\alpha c$ each step, and with noisy mini-batch gradients they keep jittering at a level that shrinks with $\alpha$.

A scheduler is an object built from the optimizer:

```python
optimizer = torch.optim.SGD(model.parameters(), lr=0.1, momentum=0.9)
scheduler = torch.optim.lr_scheduler.StepLR(optimizer, step_size=30, gamma=0.1)

for epoch in range(100):
    for x, y in train_loader:
        optimizer.zero_grad()
        loss = criterion(model(x), y)
        loss.backward()
        optimizer.step()
    scheduler.step()                        # once per epoch
    print(epoch, scheduler.get_last_lr())
```

## What you should know

- Lowering the learning rate late in training is standard; the simplest rule is "divide by 10 when the loss plateaus".
- Order: `optimizer.step()` (per batch) **then** `scheduler.step()` (per epoch, for the epoch-based schedulers).
- [`StepLR(optimizer, step_size, gamma)`](https://docs.pytorch.org/docs/stable/generated/torch.optim.lr_scheduler.StepLR.html): $\alpha_e = \alpha_0\,\gamma^{\lfloor e/\text{step\_size}\rfloor}$.
- [`ExponentialLR(optimizer, gamma)`](https://docs.pytorch.org/docs/stable/generated/torch.optim.lr_scheduler.ExponentialLR.html): $\alpha_e = \alpha_0\gamma^e$.
- [`ReduceLROnPlateau(optimizer, factor=0.1, patience=10)`](https://docs.pytorch.org/docs/stable/generated/torch.optim.lr_scheduler.ReduceLROnPlateau.html) is the lecture's "lower it when it plateaus": call `scheduler.step(val_loss)` with the metric.
- Read the current rate with `scheduler.get_last_lr()` or `optimizer.param_groups[0]['lr']`; you can also set the latter by hand.

| Scheduler | Rule (epoch $e$, start $\alpha_0$) | Typical use |
|---|---|---|
| [`StepLR`](https://docs.pytorch.org/docs/stable/generated/torch.optim.lr_scheduler.StepLR.html) | multiply by $\gamma$ every `step_size` epochs | "÷10 every 30 epochs" |
| [`MultiStepLR`](https://docs.pytorch.org/docs/stable/generated/torch.optim.lr_scheduler.MultiStepLR.html) | multiply by $\gamma$ at each epoch in `milestones` | drops at chosen epochs |
| [`ExponentialLR`](https://docs.pytorch.org/docs/stable/generated/torch.optim.lr_scheduler.ExponentialLR.html) | multiply by $\gamma$ every epoch | smooth decay |
| [`CosineAnnealingLR`](https://docs.pytorch.org/docs/stable/generated/torch.optim.lr_scheduler.CosineAnnealingLR.html) | $\eta_{\min} + \tfrac12(\alpha_0-\eta_{\min})\big(1+\cos\frac{\pi e}{T_{\max}}\big)$ | smooth decay to $\eta_{\min}$ at $T_{\max}$ |
| [`ReduceLROnPlateau`](https://docs.pytorch.org/docs/stable/generated/torch.optim.lr_scheduler.ReduceLROnPlateau.html) | multiply by `factor` once more than `patience` epochs in a row show no improvement of the metric you pass | the lecture's plateau rule |

**Check by hand.** `StepLR(step_size=30, gamma=0.1)` from $\alpha_0 = 0.1$: epochs 0–29 use $0.1$, epochs 30–59 use $0.01$, 60–89 use $0.001$, 90–99 use $10^{-4}$. `ExponentialLR(gamma=0.95)` after 10 epochs: $0.1\cdot0.95^{10} = 0.0599$.

```python
from torch.optim.lr_scheduler import ReduceLROnPlateau

scheduler = ReduceLROnPlateau(optimizer, mode='min', factor=0.1, patience=5)
for epoch in range(n_epoch):
    train_one_epoch(model, train_loader, optimizer)
    val_loss = evaluate(model, val_loader)
    scheduler.step(val_loss)                # needs the metric
```

Without a scheduler you can do the same by hand:

```python
for g in optimizer.param_groups:
    g['lr'] = g['lr'] / 10
```

> [!trap] Common mistakes
> - **`scheduler.step()` inside the batch loop** for an epoch-based schedule: `StepLR(step_size=30)` then drops after 30 *batches*, not 30 epochs.
> - **`scheduler.step()` before `optimizer.step()`**: PyTorch warns, and the first value of the schedule is skipped.
> - **`ReduceLROnPlateau.step()` without the metric** — it needs the number it watches.
> - A schedule does not rescue a bad starting rate: if $\alpha_0$ diverges in the first epoch, decaying it later is too late.
> - Tuning the schedule on the test set; it is a [[4-pytorch-training/experimental-setup|hyperparameter]], tuned on validation data.
