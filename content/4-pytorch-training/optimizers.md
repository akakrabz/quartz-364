*Lecture 10 · [[4-pytorch-training/index|PyTorch training]] · builds on [[2-calculus-and-optimization/gradient-descent|gradient descent]] and [[3-linear-models/ridge-regression|ridge regression]]*

> [!abstract] In one breath
> An optimizer holds a list of parameters and applies one update rule to all of them. You build it once, `optimizer = torch.optim.SGD(model.parameters(), lr=1e-2, momentum=0.9, weight_decay=1e-4)`, and every iteration call `optimizer.zero_grad()` before the forward pass and `optimizer.step()` after `loss.backward()`. **SGD** is gradient descent on a random mini-batch; **momentum** replaces the gradient by a running sum of past gradients; **weight decay** adds $\lambda\theta$ to the gradient, the same $L_2$ penalty as ridge regression.

## What it is

Before Lecture 10, every [[2-calculus-and-optimization/fitting-models-with-gradient-descent|fitting loop]] updated each parameter by hand inside `torch.no_grad()` and then cleared its gradient. The [`torch.optim`](https://docs.pytorch.org/docs/stable/optim.html) package does both for every parameter it was given:

| Call | Effect |
|---|---|
| [`optimizer.zero_grad()`](https://docs.pytorch.org/docs/stable/generated/torch.optim.Optimizer.zero_grad.html) | clears `p.grad` for every parameter (by default sets it to `None`) |
| [`optimizer.step()`](https://docs.pytorch.org/docs/stable/generated/torch.optim.Optimizer.step.html) | updates every parameter in place from its current `p.grad` |

`loss.backward()` is still yours: it *computes* the gradients; it does **not** change any weight.

### Stochastic (mini-batch) gradient descent

[`optim.SGD`](https://docs.pytorch.org/docs/stable/generated/torch.optim.SGD.html) is plain gradient descent; it is called *stochastic* because in practice each step uses the gradient of the loss on a random **mini-batch** of $B$ examples rather than on all $N$. If $B = N$ it is ordinary (full-batch) gradient descent.

- **Pro:** each step is $N/B$ times cheaper, so you take many more steps per pass over the data.
- **Pro:** the noise in the gradient can shake the parameters out of poor local minima.
- **Con:** noisy gradients can slow convergence near the end; the logged loss is jumpy.

## What you should know

- Build: `torch.optim.SGD(model.parameters(), lr=..., momentum=..., weight_decay=...)`. The first argument is the generator from `model.parameters()`; `lr` is the learning rate $\alpha$.
- Per iteration: `zero_grad()` → forward → loss → `backward()` → `step()`.
- **SGD with momentum** (PyTorch's form, $\mu\in[0,1)$): $G^{(k)} = g^{(k)} + \mu G^{(k-1)}$, $\;\theta^{(k+1)} = \theta^{(k)} - \alpha G^{(k)}$. Past gradient $g^{(m)}$ carries weight $\mu^{k-m}$. Typical $\mu$: 0.9 or 0.99.
- **Weight decay** $\lambda$: the gradient becomes $g + \lambda\theta$, i.e. the loss gains $\frac{\lambda}{2}\lVert\theta\rVert_2^2$ — [[3-linear-models/ridge-regression|ridge]]'s penalty. It keeps weights small; $10^{-5}$ to $10^{-4}$ is a safe start.
- The **velocity form** $v^{(k+1)} = \beta v^{(k)} - \alpha\nabla f$, $w^{(k+1)} = w^{(k)} + v^{(k+1)}$ (Spring exam formula sheet) is the same algorithm: $v = -\alpha G$.
- **Adaptive** methods ([`Adam`](https://docs.pytorch.org/docs/stable/generated/torch.optim.Adam.html), [`Adagrad`](https://docs.pytorch.org/docs/stable/generated/torch.optim.Adagrad.html), [`RMSprop`](https://docs.pytorch.org/docs/stable/generated/torch.optim.RMSprop.html)) scale the step separately for every parameter; the course uses SGD.

## SGD with momentum

Mini-batch gradients are noisy and, in a long narrow valley, plain gradient descent zig-zags across the valley while creeping along it. Momentum keeps an exponential moving average of the gradients, so components that keep the same sign build up and components that flip sign cancel:

$$
G^{(k)} = g^{(k)} + \mu\, G^{(k-1)}, \qquad \theta^{(k+1)} = \theta^{(k)} - \alpha\, G^{(k)},
\qquad G^{(k)} = \sum_{m\le k}\mu^{\,k-m} g^{(m)} .
$$

(PyTorch starts with $G^{(0)} = g^{(0)}$; its `dampening` argument, 0 by default, would multiply $g^{(k)}$ by $1-\text{dampening}$; `nesterov=True` gives Nesterov momentum.) If the gradient were a constant $g$, the step would approach $\alpha g/(1-\mu)$: momentum 0.9 is roughly a 10× larger effective step along a consistent direction.

### Worked by hand

Minimise $f(\theta) = \theta^2$ (so $g = 2\theta$) from $\theta^{(0)} = 1$ with $\alpha = 0.1$.

| step $k$ | plain GD: $\theta^{(k)}$ | momentum $\mu=0.9$: $g$ | $G$ | $\theta^{(k)}$ |
|---|---|---|---|---|
| 0 | 1 | | | 1 |
| 1 | $1 - 0.1\cdot 2 = 0.8$ | 2 | 2 | 0.8 |
| 2 | 0.64 | 1.6 | $1.6 + 0.9\cdot 2 = 3.4$ | $0.8 - 0.34 = 0.46$ |
| 3 | 0.512 | 0.92 | $0.92 + 0.9\cdot 3.4 = 3.98$ | $0.46 - 0.398 = 0.062$ |
| 4 | 0.4096 | 0.124 | $0.124 + 0.9\cdot 3.98 = 3.706$ | $0.062 - 0.3706 = -0.3086$ |

Momentum gets close to the minimum much faster, then **overshoots** (step 4) because the accumulated $G$ is still large — the oscillation in the figure above. Too much momentum with too large a learning rate can diverge, just like too large a step in [[2-calculus-and-optimization/gradient-descent|gradient descent]].

### Same algorithm, velocity form

The Spring exams' formula sheet writes momentum as

$$
v^{(k+1)} = \beta v^{(k)} - \alpha\nabla f(w^{(k)}), \qquad w^{(k+1)} = w^{(k)} + v^{(k+1)} .
$$

Substitute $v = -\alpha G$: $-\alpha G^{(k)} = -\alpha\beta G^{(k-1)} - \alpha g^{(k)}$, which is PyTorch's rule with $\mu=\beta$. Both give the table above (as long as $\alpha$ is fixed).

## Weight decay

For loss $\ell$ and weight decay $\lambda$, SGD minimises

$$
\ell_{\text{total}} = \ell(f_\theta(x), y) + \frac{\lambda}{2}\lVert\theta\rVert_2^2,
\qquad \nabla_\theta\,\ell_{\text{total}} = g + \lambda\theta ,
$$

so each step also shrinks every weight toward zero by $\alpha\lambda\theta$ — hence "decay". With $f=\theta^2$, $\alpha=0.1$, $\lambda=0.5$ and $\theta^{(0)} = 1$: $\theta^{(1)} = 1 - 0.1(2 + 0.5) = 0.75$, $\theta^{(2)} = 0.75\cdot 0.75 = 0.5625$. Purpose: discourage large weights, which overfit and react wildly to outliers, exactly as $\lambda$ does in [[3-linear-models/ridge-regression|ridge regression]]. In PyTorch the decay is applied to every parameter passed in, biases included.

```python
optimizer = torch.optim.SGD(model.parameters(), lr=1e-3,
                            momentum=0.99, weight_decay=1e-4)
```

## The lecture experiment

Lecture 10 trains the 2-D logistic-regression module on two Gaussian clusters (50 points each), batch size 16, `lr=1e-2`, and asks you to vary momentum and weight decay. Without momentum, 500 iterations reach about 97% accuracy. Things to observe when you rerun it:

- adding momentum (0.9, 0.99) makes the loss drop in far fewer iterations, but too much momentum makes it oscillate;
- adding weight decay keeps $\lVert w\rVert$ smaller, so the predicted probabilities stay softer (closer to 0.5) away from the clusters, and very large $\lambda$ hurts accuracy.

## Beyond SGD: adaptive methods

The [algorithms list](https://docs.pytorch.org/docs/stable/optim.html#algorithms) includes methods that keep per-parameter statistics of the gradient and scale each coordinate's step. **Adam** (the most common default outside this course) keeps a momentum-like average $m$ and an average of squared gradients $v$:

$$
m \leftarrow \beta_1 m + (1-\beta_1) g,\quad v \leftarrow \beta_2 v + (1-\beta_2) g^2,\quad
\theta \leftarrow \theta - \alpha\,\frac{\hat m}{\sqrt{\hat v}+\epsilon},
$$

with bias-corrected $\hat m = m/(1-\beta_1^t)$, $\hat v = v/(1-\beta_2^t)$ and defaults $\alpha = 10^{-3}$, $\beta = (0.9, 0.999)$, $\epsilon=10^{-8}$. Switching optimizer is one line: `torch.optim.Adam(model.parameters(), lr=1e-3)`. [`AdamW`](https://docs.pytorch.org/docs/stable/generated/torch.optim.AdamW.html) applies weight decay directly to the weights instead of through the gradient.

> [!trap] Common mistakes
> - **Thinking `loss.backward()` updates the weights.** It only fills `.grad`; `optimizer.step()` updates (a Spring 2026 true/false item, FALSE).
> - **No `zero_grad()`.** Gradients accumulate across `backward()` calls, so each step uses the sum of all past gradients and the run blows up. (Skipping it *on purpose* is gradient accumulation — see [[4-pytorch-training/training-loop#gradient-accumulation|the training loop]].)
> - **`step()` before `backward()`** uses the previous batch's gradient (or none at all on the first iteration).
> - **Building the optimizer from the wrong parameters**, e.g. a fresh model created after the optimizer, or parameters that were not registered with `nn.Parameter` — they never move.
> - **Re-creating the optimizer inside the loop** throws away the momentum buffer every iteration.
> - **Large momentum *and* large learning rate**: the effective step is about $\alpha/(1-\mu)$, so $\mu = 0.99$ multiplies it by 100.
