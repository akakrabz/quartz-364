> [!abstract] In one breath
> A tensor is an $n$-dimensional array of numbers of one **dtype**, living on one **device**, with a **shape** that lists the size of each dimension. It behaves like a NumPy array (and converts to one for free), but it can also live on a GPU and take part in [[2-calculus-and-optimization/autograd|automatic differentiation]]. Most exam points here are bookkeeping: predict the shape a line of code returns, and the memory a tensor takes (bytes per element × number of elements).

## What it is

Python lists can hold anything: uneven rows, mixed types, dictionaries. That flexibility makes them slow for math, and `+` on lists **concatenates** instead of adding. NumPy arrays store one type in one block of memory and vectorize elementwise math; in the lecture, adding two length-$10^6$ vectors took 0.253 s with a list comprehension and 0.011 s with NumPy, about **23× faster**.

A PyTorch [`torch.Tensor`](https://docs.pytorch.org/docs/stable/tensors.html) is the same idea, with almost the same functions and attributes as a NumPy array, plus two things NumPy lacks: it can sit in GPU memory, and it can record the operations applied to it so gradients can be computed.

In linear-algebra terms a **scalar** has no index, a **vector** $v\in\mathbb{R}^n$ one, a **matrix** $A\in\mathbb{R}^{m\times n}$ two (rows first: **row-major**), and a **tensor** $N\ge 3$. In PyTorch all of them are `Tensor`s with `ndim` 0, 1, 2, 3, ….

## What you should know

- Create tensors with `torch.tensor(data)`, `torch.zeros/ones/rand/randn(shape)`, `torch.arange`, `torch.linspace`, `torch.randint(low, high, size)`; `high` and `arange`'s stop are **excluded**.
- Default dtypes: Python floats → `float32`, Python ints → `int64`; `torch.zeros`, `rand`, `linspace` → `float32`; `arange(N)`, `randint` → `int64`.
- Bytes per element: `int8`/`uint8`/`bool` 1, `int16`/`float16` 2, `int32`/`float32` 4, `int64`/`float64` 8. Memory $=$ `a.element_size() * a.nelement()`.
- Pick the **smallest dtype that holds the data** (image intensities 0–255 → `uint8`) and a shape whose dimensions you can name, e.g. `(images, channels, height, width)`.
- `torch.cat` joins along an **existing** dimension (that size grows); `torch.stack` creates a **new** dimension (of size = number of tensors).
- `unsqueeze(d)` inserts a size-1 dimension at position `d`; `squeeze(d)` removes it.
- Elementwise functions (`torch.exp`, `log`, `cos`, `abs`, …) **return a new tensor**; the underscore versions (`a.exp_()`) change `a` in place ([[1-foundations/storage-and-views|storage and views]]).
- `t.numpy()` and `torch.from_numpy(arr)` share memory with each other (CPU only).

## Creating tensors

```python
data = [[1, 2, 3, 4],
        [5, 6, 7, 8]]
t = torch.tensor(data)             # copies data, int64
t2 = torch.from_numpy(np.array(data))  # shares the array's memory

shape = (2, 3, 4)
z = torch.zeros(shape)             # float32 zeros
o = torch.ones(shape)
r = torch.rand(shape)              # uniform on [0, 1)
g = torch.randn(shape)             # standard normal
i = torch.randint(low=0, high=100, size=(10, 10))  # ints in [0, 100)
a = torch.arange(10)               # 0, 1, ..., 9 (int64)
x = torch.linspace(-10, 10, 1000)  # 1000 points, both ends included
```

| Call | Values | dtype | Shape |
|---|---|---|---|
| `torch.arange(N)` | $0, 1, \dots, N-1$ | `int64` | `(N,)` |
| `torch.arange(42).view(3, -1)` | $0..41$, rows of 14 | `int64` | `(3, 14)` (the `-1` is inferred) |
| `torch.linspace(a, b, n)` | $n$ points from $a$ to $b$ inclusive | `float32` | `(n,)` |
| `torch.randint(low, high, size)` | integers in $[\text{low}, \text{high})$ | `int64` | `size` |
| `torch.rand(s)` / `torch.randn(s)` | uniform $[0,1)$ / $\mathcal N(0,1)$ | `float32` | `s` |
| `torch.tensor([1.0, 2])` | as given | `float32` | `(2,)` |
| `torch.Tensor([1, 2])` (capital T) | as given | `float32` | `(2,)` |

NumPy's `np.random.rand(2, 3, 4)` wants the sizes unpacked; PyTorch accepts either `torch.rand(2, 3, 4)` or `torch.rand((2, 3, 4))`.

### Attributes for debugging

```python
tensor = torch.rand(3, 4)
print(tensor.shape)   # same as tensor.size()

```

Also useful: `tensor.ndim` (number of dimensions), `tensor.nelement()` or `tensor.numel()` (number of elements), `tensor.element_size()` (bytes per element). Most bugs in this course are shape, dtype or device mismatches, and these three attributes find them. See [tensor attributes](https://docs.pytorch.org/docs/stable/tensor_attributes.html).

## Choosing a shape for data

Name every dimension. The Lecture 2 exercise:

| Data | Shape | Dimensions |
|---|---|---|
| 8 stereo audio clips, 100,000 samples each | $(8, 2, 100000)$ | clip, channel (L/R), sample |
| 2-minute video at 30 fps, RGB frames of $512\times1024$ | $(3600, 3, 512, 1024)$ | frame, color, height, width |
| 4 cultures × 6 wavelengths × 100 z-slices (1 mm at 10 µm) of $256\times256$ | $(4, 6, 100, 256, 256)$ | culture, wavelength, z, height, width |

An RGB image is a 3-D tensor $(3, H, W)$ (channel first, the PyTorch convention), and a batch of them is 4-D $(N, 3, H, W)$; the [[1-foundations/what-is-machine-learning#the-lecture-1-demo-a-pretrained-resnet-18|ResNet demo]] feeds the model a $(1, 3, 224, 224)$ batch.

## Data types and memory

| dtype | aliases | bytes per element |
|---|---|---|
| `torch.int8` / `torch.uint8` | char / unsigned char | 1 |
| `torch.bool` | | 1 |
| `torch.int16`, `torch.float16` | short, half | 2 |
| `torch.int32`, `torch.float32` | int, `torch.float` | 4 |
| `torch.int64`, `torch.float64` | `torch.long`, `torch.double` | 8 |

$$
\text{bytes} = \texttt{a.element\_size()} \times \texttt{a.nelement()}
$$

```python
a = torch.zeros([2, 5], dtype=torch.int32)
print(a.element_size() * a.nelement())   # 4 * 10
b = torch.ones([3, 5], dtype=torch.float64)
print(b.element_size() * b.nelement())   # 8 * 15
c = torch.rand([8, 128, 224, 224], dtype=torch.float64)
print(c.element_size() * c.nelement() / 2**20, 'MB')
```

```
40
120
392.0 MB
```

The last one: $8\cdot128\cdot224\cdot224 = 51{,}380{,}224$ elements $\times\ 8$ bytes $= 411{,}041{,}792$ bytes $= 392$ MiB. In `float32` it would be half that, 196 MiB.

> [!example] HW 1 Q2 — one million $256\times256$ RGB images, one byte per channel
> ```python
> images = torch.zeros((1_000_000, 3, 256, 256), dtype=torch.uint8)  # (image, channel, row, col)
> ```
> `uint8` is the most efficient choice because each intensity (0–255) fits in one byte. Size: $10^6\cdot 3\cdot 256\cdot 256 = 1.966\times10^{11}$ bytes $\approx 197$ GB (183 GiB). The default `float32` would need four times as much, about 786 GB.

Convert with `.to(dtype)` or the shortcuts `.float()`, `.double()`, `.long()`, `.int()`:

```python
x = torch.ones((2, 4), dtype=torch.int32)
y = x.to(torch.float64)   # new tensor, x unchanged
```

Memory matters because data must fit where the computation happens. The lecture's memory hierarchy: caches are tiny and fast, CPU RAM is gigabytes, GPU RAM is fast but limited, disks are large and slow. *Where is the data, how do I get it there, and does it all fit at once?* — "Don't ignore these aspects ever!"

```python
a = torch.randn(2, 3)
torch.cat((a, a, a), dim=0).shape    # (6, 3): rows grow
torch.cat((a, a, a), dim=1).shape    # (2, 9): columns grow
torch.stack((a, a, a, a), dim=0).shape  # (4, 2, 3)
torch.stack((a, a, a, a), dim=1).shape  # (2, 4, 3)
torch.stack((a, a, a, a), dim=2).shape  # (2, 3, 4)
```

> [!key] Shape rules
> - `torch.cat` of tensors with shapes that agree **everywhere except dimension `d`**: the result has the sum of their sizes in dimension `d`.
> - `torch.stack` of $k$ tensors of **identical** shape $S$ at dimension `d`: the result is $S$ with a new size-$k$ dimension inserted at position `d`. With `dim=-1` it goes last.
> - Both allocate new memory.

`stack((a, a, a, a), dim=2)` puts the four copies side by side in the last dimension, so `d[i, j, :]` is four copies of `a[i, j]`, exactly what the lecture printed.

## Adding and removing dimensions

```python
a = torch.randn(2, 3)
b = a.unsqueeze(1)    # (2, 1, 3)
c = b.squeeze(1)      # (2, 3)
a.unsqueeze(0).shape  # (1, 2, 3)
a.unsqueeze(-1).shape # (2, 3, 1)
```

- `unsqueeze(d)` makes room for a batch dimension (`img.unsqueeze(0)`), or turns a vector into a column `(n, 1)` for [[1-foundations/broadcasting|broadcasting]].
- `squeeze(d)` removes dimension `d` only if its size is 1; `squeeze()` with no argument removes **every** size-1 dimension, which can surprise you when a batch has one example.
- `permute(1, 2, 0)` reorders dimensions; the ResNet demo uses it to turn a $(3, H, W)$ tensor into the $(H, W, 3)$ layout `matplotlib` expects.
- `view` and `reshape` change the shape without changing the number of elements ([[1-foundations/storage-and-views|storage and views]]).

All of these return **views** that share memory with the original (`reshape` only when it can; otherwise it copies).

## Converting to and from NumPy

```python
tensor = torch.ones(4, 4)
arr = tensor.numpy()            # shares memory
back = torch.from_numpy(arr)    # shares memory too
copy = torch.tensor(arr)        # independent copy
```

Changing `arr` changes `tensor`. `.numpy()` only works on a CPU tensor that does not require gradients: call `.detach().cpu().numpy()` on model outputs before plotting. Note that NumPy's default float is `float64`, so `torch.from_numpy(np.random.rand(3))` is a `float64` tensor.

## Elementwise math

Functions such as [`torch.cos`](https://docs.pytorch.org/docs/stable/generated/torch.cos.html), `torch.sin`, [`torch.exp`](https://docs.pytorch.org/docs/stable/generated/torch.exp.html), [`torch.log`](https://docs.pytorch.org/docs/stable/generated/torch.log.html) and `torch.abs` apply to every element and **return a new tensor**. Each also exists as a method (`a.exp()`) and an in-place method (`a.exp_()`).

> [!example] Lecture 2 exercise — sigmoid with temperature and shift
> The **sigmoid** $\sigma(x) = \dfrac{1}{1+e^{-x}}$ goes from 0 to 1 and equals $0.5$ at $x=0$. A temperature $\tau$ stretches it and $b$ moves its center:
> ```python
> def my_sigmoid_a(x, tau):
>     return 1 / (1 + torch.exp(-x / tau))    # sharper for small tau
>
> def my_sigmoid_b(x, b):
>     return 1 / (1 + torch.exp(-(x - b)))    # 0.5 at x = b
> ```
> Check: $\tau = 1$ and $b = 0$ give back the ordinary sigmoid ([`torch.sigmoid`](https://docs.pytorch.org/docs/stable/generated/torch.sigmoid.html)).

> [!trap] Common mistakes
> - **Stop is excluded**: `torch.arange(5)` ends at 4, `torch.randint(0, 100, …)` never returns 100, `torch.randint(low=-9, high=9, …)` stops at 8.
> - `torch.cat` does **not** add a dimension; `torch.stack` does. `stack` of a list of (2, 3) tensors cannot have shape (2, 3).
> - `torch.Tensor([1, 2])` is `float32`; `torch.tensor([1, 2])` is `int64`. Integer tensors break functions that need floats, such as [[1-foundations/linear-algebra-in-pytorch#norm|`torch.norm`]] and `torch.inverse`; convert with `.float()`.
> - Memory questions count **bytes**, not bits, and the lecture's "MB" divides by $2^{20}$.
> - `squeeze()` with no argument can remove the batch dimension.
